# Plan a day

Follow the [3PO operating contract](../../references/3po-contract.md).

Resolve the intended day from the client's date/time and relevant local timezone. Read the applicable Assistant/Brief and planning-related guidance. Read that day's Calendar range and incomplete Reminders, then relevant project tasks. Retrieve only the project/topic context needed to interpret priorities.

Read saved attention/Review when the user asks for a brief or when it materially affects the plan. Label its freshness. Read weather when it affects the proposed activities. Do not initiate a background scan or treat a saved Brief as newly generated by 3PO.

Build around actual commitments, realistic capacity and the user's stated priorities. Separate existing events, proposed work blocks and unscheduled tasks. Report a source failure or capped coverage instead of assuming free time.

Give a concise brief or workable sequence, with important conflicts and an essential clarification only when needed. Avoid forcing an hourly timetable if a priorities list better answers the request.

A request to plan produces a proposal in this conversation. If the human also requested saving specific changes, read their exact targets and use the domain tools sequentially. Existing authorisation still applies; do not ask again merely because the plan has become concrete. Confirm each saved outcome separately.
