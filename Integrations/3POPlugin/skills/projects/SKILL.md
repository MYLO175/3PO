# Work with Projects

Follow the [3PO operating contract](../../references/3po-contract.md).

Read Project instructions and the relevant workspace branch with read_life_items. Use the maintained project page and parent/child index to understand purpose. Current human descriptions and item state take priority over an older summary.

Choose the requested existing parent, status and destination from issued records. Before a move, edit, deletion or ordering change, inspect the affected parent/child records. Do not infer completion from a passed deadline.

Use create_life_items, change_life_item, delete_life_item and reorder_life_item for actual requested structural changes. Use link_life_item/unlink_life_item for relationships, preserving the separate native/source identities.

Use read_project_notes before change_project_note. A change to one original or additional note card preserves all other cards and unrelated structure. Read Recently deleted for an exact restore_life_item target.

Call show_project_view only when the user asks to open/show a view. Do not rearrange the dashboard as a side effect of explaining a project.

Return an understandable structure, practical plan or verified change result. Identify genuine duplicate records without silently merging them. Project status and native Reminder completion remain separate even when the records are linked.
