# Life and project workspace

Projects contains just **spaces and tasks**. A space is a folder: it can hold other spaces and tasks, with optional notes written directly inside it. A task is local project work, separate from Apple Reminders. Universities, courses, modules and projects are names you give spaces, rather than different item types. A record keeps its identity when renamed or moved. Siblings are records sharing a parent; cross-branch relationships add related, depends on, prepares for, supports and other useful connections.

For example, a study area can contain a university, then Engineering, then modules and a project. The project can contain research, implementation and evaluation sections with their work. This is a flexible shared foundation: a widget displays the same records the PA reads and edits.

## Using it

Choose **Projects** in the Life map, or add a **Projects** widget. Think of it as folders containing folders, notes and work: **Engineering → Modules → Signals**, or **Engineering → Sensor Garden → Research**. Click any visible part of the path to go there. A narrow widget puts earlier parents in a small path menu. Browsing never changes the widget's saved opening folder.

Home shows top-level spaces only. Tasks without a folder remain available through **Unfiled tasks**; this is a local browsing entry, not a newly authored project. Opening a folder shows its direct contents. Work stays in that folder rather than being gathered onto Home. There is no persistent search bar; the PA can still search the entire permitted hierarchy.

Folders & tasks is the default view: folder tiles followed by a board where the folder has tasks. The board has **To do / In progress / Done**. List is an alternative; Tree and Deadlines are tucked under More views. Tree deliberately expands a hierarchy; other views stay at the current folder. Home always uses folder tiles, even if a work view was previously selected. Hide finished tasks filters task cards without hiding navigation folders or changing actual progress.

A small segmented bar shows the split of known work below a folder, with percentages when the folder is open. Purple means To do, amber In progress, and green Done. Progress counts actual saved tasks (including old milestones displayed as tasks), not attendance, mastery or unrecorded work. Archived work is excluded. Existing Waiting records stay saved as Waiting and appear under To do with their label; displaying the three-stage board does not rewrite them. Drag a task card into any board column, including an empty column or onto an existing card. The card follows your pointer and the destination is highlighted; releasing saves its stage and updates the counts/progress bar. Releasing outside the columns leaves it unchanged. A normal click still opens details, and the checkbox still completes a task. Its menu and detail page also offer stage controls. Stage moves affect local project work only and refuse a changed account, folder or revision. Supported last edits can be undone in the current session.

Use + to add **Space** or **Task**, at home or inside a space; **Add a task…** saves on Return and retains a failed draft. Checkboxes complete a local workspace task, independently of any linked Apple Reminder. Creation has no app Undo; use recoverable Delete if necessary. Old course/project/area/folder/note entries are presented as spaces; old milestones as tasks. Compatibility metadata is retained internally so opening an old record does not change its identity, revision, notes, nesting, status, source references or typed memory associations. New UI and AI creation expose only space/task. Only spaces are offered as parents; moving into a task or converting a space with contents into a task is refused.

**Add a note…** opens the folder's notes editor. Saved notes sit quietly above its contents, with a pencil to edit. Save/Cancel captures the original account and revision; an outside change leaves the draft open rather than overwriting it. Saved notes use existing revision-checked session Undo. The folder's ellipsis menu contains details, Move, Delete and **Connections & organisation** for source links, PA evidence and unfinished filing suggestions. Opening this inspection makes no AI or source request. **Suggest a folder** explicitly resumes a paused filing suggestion. **Open this folder by default** sets that widget's opening bookmark; **Open Projects home by default** clears it. Recently deleted remains in the same menu.

You can also describe a structure naturally to the PA: “Set up a study area containing Example University, Engineering, two modules called Signals and Mechanics, and a project called Sensor Garden.” Follow up with understood edits such as “I've finished Read paper”, “Move Research under Sensor Garden” or “Link Sensor Garden to Signals”. The PA reads exact records before changes and asks only for a genuinely missing target or decision. A hierarchy of up to twelve records can be created atomically. Larger requested structures can use successive progressing operations; foreground work has no fixed round/call count cap. Individual operation/payload bounds, cancellation, ownership and duplicate checks still apply.

The PA can change an existing Projects widget's branch/view after reading it, for example “Show unfinished work in Engineering in my Projects widget.” Creating widgets stays in the dashboard controls. Widget view changes use existing layout Undo. One most-recent local record or structural edit per account supports session-only Undo with fresh revision checks. Move, sibling ordering, recoverable deletion and restore participate; every affected record is checked before a multi-record Undo. Creation and relationship changes have no app Undo; relationships can be explicitly unlinked.

The Life map’s **Map** is the graphical overview of life areas and their connections. Select an area to see saved branches and evidence and open their same editable records. **Projects** is the editable workspace, with Tree available for a collapsible hierarchy; Notes retains evidence-backed facts. The old internal Structure tag and existing record/widget identities remain intact. The views share identities and area placement, including inherited parent areas.

## Memory, work and sources

A memory is a belief with evidence, origin and correction history. A project record is an editable place or item of work. Neither silently replaces the other. **Link something** connects a record to another local record, a permitted current memory, an available Calendar event, Reminder, Mail header or selected WhatsApp message. Source links store pointers, including account/container and linked-message identity/version where relevant; they do not copy source bodies into project notes.

The PA can make these same connections after reading the exact permitted endpoint. Removing a relationship retains both endpoints. Disabled, changed or uncached sources appear unavailable, with their identity/content withheld from tool results; lack of cached coverage does not mean the source was deleted. Mail remains read-only. Linked Apple events/reminders retain their own authoritative dates and completion state: completing a local task does not complete an attached Reminder.

Normal conversation learns life context through memory; mentioning a course or project does not create workspace content. Explicit setup/create/import intent or acceptance of a concrete proposal is required. PA-created records retain the originating turn and human quote for inspection. Imported text and old memory remain data; they never grant write permission. Imported structures require current human setup/import intent, and the PA must not invent personal work, attendance, mastery, progress, dates or estimates.

## Reliability and current limits

Records are scoped to the active registration; legacy topic scopes remain isolated unless the captured Focus conversation permits them. Saves validate scope, field bounds, exact parent identity, hierarchy/dependency cycles and current revision. Project writes and their canonical operation receipts commit together, so a completed operation can be recognised without creating another copy. Unsupported/corrupt storage is preserved and editing disabled rather than replaced with an empty notebook. Existing memory, transcripts, native receipts and layouts are not migrated.

Normal refresh, source reception and widget display never enqueue project inference. New spaces save directly in the chosen home without an automatic placement request. The PA can create or file spaces/tasks when you ask. Existing older placement requests remain inspectable and resumable; see below. Existing separately opted-in memory/source learning is unchanged. Source-driven association proposals, ongoing background project maintenance, semantic aliases/consolidation, finer Focus selection, file attachments and richer schedules remain future units. This increment provides an editable shared structure and source pointers, not a claim that the PA understands every part of your life.

Validation evidence and installed/live boundaries are in [STATUS](../STATUS.md). All test projects use fictional data in disposable storage.


## Memory links and older placement requests

New spaces are generic folders. **Match PA understanding** can bind a space to an exact permitted saved course/project/organisation identity. A generic folder with a similar name is not automatically merged. This reviewed association survives renaming, and disappears from the memory projection when its evidence is no longer available. Existing typed associations are retained. Workspace type and the PA's understanding are distinct: a space may represent a course without needing a Course item type.

The following bounded placement behaviour applies to retained older project requests. New Space/Task creation no longer queues it or shows the former automatic-placement toggle. Existing request identities, pauses and chosen parents remain saved.

The pass reads the project's title/notes/direct headings, bounded same-scope saved items and usable human memory. It can choose an existing home and up to four supported item cross-links, and attach exact memory identities. Clearly stated typed organisations/courses in human memory can supply stable candidate anchors; only paths/anchors actually used in the result are saved. It never creates invented tasks, edits headings/content/work dates/status, changes a personal fact, reads fresh sources or writes Apple apps. Source-origin memories are excluded from this placement inference. Imported/project text is data, never operational authorisation.

Clear placement is applied directly with a brief explanation. A genuinely ambiguous project retains its current home and asks one short question with two or three choices, available in Connections & organisation and the captured PA thread. Choosing there places it locally without another inference; free typing/PA answer buttons remain available through normal human-intent tools. A manual correction pins the chosen home. Parent placement edits participate in revision-safe session Undo; generated cross-links/anchors are retained and explicitly removable/editable rather than claiming global Undo.

The notebook is a read-only projection of current facts and durable items. Unique exact same-scope non-person typed names resolve to saved IDs; explicit memory identity links preserve a project's identity through renaming. Memory-created course/organisation anchors keep a canonical notebook identity. Ambiguous matches and equal contact names do not silently merge. Original facts, evidence and correction lineage remain saved; unusable/forgotten/excluded memories disappear from the projection. Foreground PA context includes bounded hierarchy/path and cross-link data, with exact item exploration through read_life_items.

Placement has a persisted request identity/status/result. It captures account, project/store revision, selected model and permitted-memory/access ownership before inference. Stale output is rejected. Failed or interrupted requests pause and require the explicit Suggest a folder action; they do not automatically replay on relaunch. If the connection is unavailable, pending work waits. Normal refresh remains no-AI; only an existing human-created placement request can be serviced by the idle dispatcher. There is one inference attempt per request, serial with existing AI jobs, without an API-key or billing fallback.


## Your workspace, and the PA’s understanding

Projects, headings, tasks, notes and filing are your workspace. The PA can help when you ask, or when you accept a concrete proposal; it does not create projects merely because it learns about your life. Background placement can create only supported course/organisation navigation anchors, link an existing project and organise its life context. It never authors project work. Existing records remain human-owned; optional ownership metadata requires no migration.

Use an item’s context menu or detail menu for **Move**, **Delete** and **Match PA understanding**. Move chooses a parent and sibling position. In Tree, disclosure arrows open folders, dragging onto a folder moves inside it, and insertion targets order siblings on release. Expansion is saved per widget/account. A manual move pins a project’s chosen home. Match PA understanding binds a human-reviewed typed memory identity through later renaming; an existing duplicate durable identity must be resolved manually first. No fuzzy merge or fact rewrite happens.

Delete moves an item to **Recently deleted**, preserving its identities, notes, relationships and descendants. For a folder you can retain its contents in the old parent instead. Restore brings back the same records; if the former parent remains deleted, the restored branch goes home. There is no permanent purge control. Automatic placement cannot resurrect deleted matching anchors/projects, and restored placement stays paused until you choose to continue.

A heartbeat may propose a new project in PA chat or Review inbox. **Review space** opens an editable space form. Only Save creates it, with a receipt and exact source pointer; merely receiving the suggestion does not. A previously saved proposal displays Created, preventing another copy.
