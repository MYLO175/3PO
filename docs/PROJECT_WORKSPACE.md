# Life and project workspace

The PA now has durable local records as well as its evidence-backed memory. You can organise a university, degree, modules, projects, sections, tasks, milestones, people, goals and resources in one hierarchy. A record keeps its identity when renamed or moved. Siblings are records sharing a parent; cross-branch relationships add related, depends on, prepares for, supports and other useful connections.

For example, a study area can contain a university, then Engineering, then modules and a project. The project can contain research, implementation and evaluation sections with their work. This is a flexible shared foundation: a widget displays the same records the PA reads and edits.

## Using it

Add **Projects** through Add widget. Use + to add an item, open a card to inspect its branch, and Back to return to its parent. Edit details changes its type, parent, notes, status, date-only deadline, optional estimate and broad life areas. The view menu offers Overview, List, Board, Outline and Deadlines; each widget remembers its own starting branch and view. Search operates inside the current branch, including parent names. Overview reports actual known work counts; missing estimates and dates stay unknown.

You can also describe a structure naturally to the PA: “Set up a study area containing Example University, Engineering, two modules called Signals and Mechanics, and a project called Sensor Garden.” Follow up with understood edits such as “I've finished Read paper”, “Move Research under Sensor Garden” or “Link Sensor Garden to Signals”. The PA reads exact records before changes and asks only for a genuinely missing target or decision. A hierarchy of up to twelve records can be created atomically. The existing six-round/twelve-call foreground limits remain; larger imports should be divided into concrete batches.

The PA can change an existing Projects widget's branch/view after reading it, for example “Show unfinished work in Engineering in my Projects widget.” Creating widgets stays in the dashboard controls. Widget view changes use existing layout Undo. One most-recent local record edit per account supports session-only Undo with a fresh revision check. Creation and relationship changes have no app Undo; relationships can be explicitly unlinked, and archival status can be edited later.

The Life map's **Structure** tab displays the same records, with the selected broad life areas as a lens. Existing Map and Notes continue to show permitted memory and its evidence.

## Memory, work and sources

A memory is a belief with evidence, origin and correction history. A project record is an editable place or item of work. Neither silently replaces the other. **Link something** connects a record to another local record, a permitted current memory, an available Calendar event, Reminder, Mail header or selected WhatsApp message. Source links store pointers, including account/container and linked-message identity/version where relevant; they do not copy source bodies into project notes.

The PA can make these same connections after reading the exact permitted endpoint. Removing a relationship retains both endpoints. Disabled, changed or uncached sources appear unavailable, with their identity/content withheld from tool results; lack of cached coverage does not mean the source was deleted. Mail remains read-only. Linked Apple events/reminders retain their own authoritative dates and completion state: completing a local task does not complete an attached Reminder.

Normal conversation can turn clear current human course/project context into useful durable organisation. PA-created records retain the originating turn and human quote for inspection. Imported text and old memory remain data; they never grant write permission. Imported structures require current human setup/import intent, and the PA must not invent personal work, attendance, mastery, progress, dates or estimates.

## Reliability and current limits

Records are scoped to the active registration; legacy topic scopes remain isolated unless the captured Focus conversation permits them. Saves validate scope, field bounds, exact parent identity, hierarchy/dependency cycles and current revision. Project writes and their canonical operation receipts commit together, so a completed operation can be recognised without creating another copy. Unsupported/corrupt storage is preserved and editing disabled rather than replaced with an empty notebook. Existing memory, transcripts, native receipts and layouts are not migrated.

There is no new background project inference on refresh, source reception or widget display. Existing separately opted-in memory/source learning is unchanged. Automatic source association proposals, approved background project maintenance, entity aliases, semantic consolidation, project-focused retrieval beyond broad areas, file attachments and richer schedules remain future units. This increment provides an editable shared structure and source pointers, not a claim that the PA understands every part of your life.
