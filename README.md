# Mission Control
A local native macOS dashboard for Apple Calendar, Reminders and Mail. The dashboard remains local. Stage 2 adds optional subscription-powered chat, email summaries and a saved morning briefing. Personal sources are sent only when their AI controls are enabled.

## Run
Requires macOS 26+, Xcode and an Apple Development signing identity. The installed app is `~/Applications/Mission Control.app`. Open it and grant Calendar full access, Reminders access and Automation access to Apple Mail when macOS asks. Permissions belong to this app, not helper scripts.

## Build
```sh
./scripts/build.sh
./scripts/test.sh
open '/tmp/missioncontrol-derived/Build/Products/Debug/Mission Control.app'
```
The build regenerates the macOS icon from `MissionControl/Resources/AppIcon.png` using the bundled icon script and macOS sips. The menu bar uses a matching monochrome template symbol.

The build uses `/Applications/Xcode.app/Contents/Developer` without changing global settings, and writes derived output under `/tmp` to avoid Finder metadata interfering with signing. `scripts/generate-project.py` regenerates the normal Xcode project from Swift/JS files; open `MissionControl.xcodeproj` for editing. Signing team is configured for this Mac's existing identity; change `DEVELOPMENT_TEAM` in the generator when building elsewhere.

## Behaviour
- Compact three-panel dashboard; narrower windows place Inbox below Calendar and Reminders.
- Selected-day/tomorrow agenda and seven-day overview, including all-day and overlapping events.
- Calendar bars use Apple Calendar source colours. Reminders default to their Apple lists, with To do first and an optional Due date grouping; identity-based completion with one-level Undo. Read-only lists cannot be edited.
- Dynamically discovered account inboxes, last 30 days, with mailbox filters. The reader starts with today and works backwards in calendar-day windows, fetching at most 20 headers per page. Each page and its stable ID cursor are saved together; partial results appear immediately. Coverage shows completed date windows per account (31 calendar dates can overlap a rolling 30-day interval). Timeouts pause automatic reads; Refresh resumes progress. Plain-text bodies load only for a preview. No attachments or outgoing mail; normal dashboard refresh makes no AI requests.
- Manual/launch/wake refresh, EventKit change observation, Mail polling every five minutes. Errors retain last successful cache and show stale/error state.
- Source filters persist. Caches are stored with SwiftData in `~/Library/Application Support/Mission Control`, excluded from Git. Preferences use the app's UserDefaults domain.
- Closing the window keeps the menu bar app alive. Open it again from the menu bar. Explicit Quit stops it. Settings offers launch at login through Apple's SMAppService.

## Initial assistant
Click Assistant in the dashboard to open or collapse streaming chat. Conversations are saved locally, separated by ChatGPT registration. Stop preserves partial output without treating it as complete. Settings includes editable preferences and independent AI calendar/list/account exclusions. Source context defaults off; when enabled, messages send bounded calendar/reminder snapshots, the latest 20 email headers and up to 20 saved email summaries through your ChatGPT plan. Saved summaries include source IDs, evidence and partial coverage; full bodies are not resent by chat. Explicit create/edit/complete requests use defined Calendar/Reminders actions. Imported sources cannot authorise writes; email stays read-only. The initial action grammar accepts requests starting with create/add/schedule/edit/change/move/reschedule/complete/mark, optionally preceded by please or can/could/would you. Other chat remains read-only.

`./scripts/test-stream.sh` checks response deltas, completion and failed/incomplete/interrupted streams.

## Email overview checkpoint
The primary panel is a general AI overview across upcoming calendar commitments, incomplete reminders and retained email follow-ups. Sources opens the existing mailbox-filtered headers and previews. Settings → Automatic email summaries explains plain-text body transmission through your ChatGPT plan and enables independent processing. It defaults off. Each five-minute worker pass assesses up to 20 incoming headers and reads at most three selected bodies. Monitoring starts with today; it does not analyse the historical 30-day inbox. Obvious ignorable mail is omitted, with ambiguous or potentially relevant headers selected for body reading. Header triage is heuristic and can miss a relevant message; explicit mail questions can retrieve older content. Invalid completed model output is skipped per message and saved as rejected progress; other messages continue. Retry skipped explicitly permits another bounded attempt. Connection, read, storage and usage-limit errors pause processing until explicit Resume. Header fingerprints reuse unchanged summaries; body-only changes are checked in bounded batches using hashes, rotating through records older than 24 hours. Large backlogs can make rechecks take longer than a day; unchanged bodies do not trigger inference. Monitoring status shows pending incoming assessment and retained follow-ups. The secondary Sources view shows raw Mail import coverage. Summaries are separated by ChatGPT registration and respect AI account exclusions. Needs-attention cards require a verbatim quote present in the supplied body/subject and link to the actual message preview. This validation does not prove every model claim is accurate. ## Requested Calendar and Reminders actions
With assistant source context enabled, clear requests can create/edit events and create/edit/complete reminders. Calendar defaults to Apple's writable default; reminders default to the unique enabled writable To do list. Missing or ambiguous dates, duration, destination, or targets require clarification. Duplicate titles require an explicit source or a target selection. Recurring event edits support only an explicitly chosen single occurrence; recurring creation, reminder-series editing and deletion are deferred. New titles must appear in the user's request.

Planning uses a bounded fresh Calendar/Reminders snapshot without imported email text. Native execution resolves exact identifiers, rechecks the original snapshot and writable/enabled sources, then refetches and verifies the save. A persisted attempt receipt prevents automatic repeats after an uncertain save. An identical verified request within ten minutes returns its previous result; an explicit different selected target is a separate request. Completion offers Undo. AI summaries and scheduled briefings have no write operations.

`./scripts/test-actions.sh` checks request intent, unsupported operations, local-date/DST handling and stable duplicate keys. ## General overview and older-mail questions
“What’s going on” ranks at most six priorities across the next seven days and wider outstanding work, with reasons and source references. It uses enabled Calendar/Reminders and retained email assessments rather than summarising every message. An independent fifteen-minute check refreshes only when its stable input changes; manual Update overview can explicitly regenerate. Normal source refresh has no AI request. The live overview is separate from the saved daily briefing and produces no notification. It is stored locally per subscription registration and hidden when AI source settings change until rebuilt.

Email follow-ups are collapsible and can be dismissed. New mail is assessed from the monitoring start day onward. Important future dates include an exact supporting quote, are retained beyond the 30-day header cache and are supplied to the general overview/briefing. Existing assessments remain local; there is no automatic historical-summary job.

Ask “Find the email from [sender/topic] in [date range]” or ask about an old email with its approximate date. This invokes a separate read-only header search over enabled account inboxes, then reads up to three matching bodies for the answer. It scans at most eight 20-header pages per user operation, using daily windows and a continuation cursor. Continue mail search resumes additional bounded reads. Mail sources opens matching originals, including messages older than the dashboard's 30 days. Dates are limited to a one-year interval per search, although that interval can be in the past. Search keywords match sender or subject, not full-body-only terms, and archived/sent folders are outside the inbox scope. Partial results never prove an email absent. Search cursors are currently session-local; saved conversations persist, but a relaunch requires a new search.

`./scripts/test-mail-lookup.sh` checks explicit mail routing, literal meaningful keywords and sender/subject matching. `test-summaries.sh` additionally checks monitoring cutoff, header alias validation and future-date/source-metadata persistence. ## Optional dictation
Your existing system dictation shortcut works in the assistant message field. The optional microphone button opens an editable transcript sheet, initially English (UK). Start requests macOS Speech Recognition and microphone consent; recording stops after one minute, on cancellation, sleep or session lock. Stop lets you review the captured text. Use transcript places it in the message field, and Send remains a separate action. Typed input remains available when permission, input or on-device assets are unavailable. No audio is saved or sent through OpenAI. The implementation requires both Apple's on-device capability and `requiresOnDeviceRecognition`; no cloud fallback is used. [Apple capability documentation](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition), [request documentation](https://developer.apple.com/documentation/speech/sfspeechrecognitionrequest/requiresondevicerecognition).

User has deprioritised built-in dictation in favour of their existing shortcut. Further development should focus on the general overview, incoming-mail monitoring and morning briefing rather than expanding voice features.
